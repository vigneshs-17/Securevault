# Security Policy

## Supported Versions

Only the latest commit on the `main` branch of SecureVault is officially supported for security updates.

| Version | Supported          |
| ------- | ------------------ |
| `main`  | :white_check_mark: |
| < 1.0   | :x:                |

## Reporting a Vulnerability

We take the security of SecureVault seriously. If you believe you have found a security vulnerability in this repository, please report it responsibly:

- **Reporting Channel:** Please report vulnerabilities via [GitHub Private Vulnerability Reporting](https://github.com/vigneshs-17/Securevault/security/advisories/new) (accessible via the **Security** tab → **Advisories** → **Report a vulnerability**).
- **Confidentiality:** Please do not report security vulnerabilities through public GitHub issues, discussions, or pull requests.

### Response Commitment

- **Response SLA:** We operate on a **best effort** basis and aim to respond to all incoming vulnerability reports within **7 days**.
- **Assessment:** Once received, reports will be evaluated for severity, exploitability, and potential impact. If accepted, a patch will be prepared and coordinated through private advisory workflows before release.

### What to Include

To help us triage and resolve your report efficiently, please include:
- A description of the vulnerability and its potential security impact.
- Affected component, route, or file and line numbers.
- Detailed reproduction steps or theoretical exploit scenario (please avoid running destructive actions).
- Suggested remediation or patch, if available.
